# Integrating a subtask (the local merge)

The section "Subtask PRs" of `SKILL.md` moved here and was rewritten on 2026-11-19: a subtask is not a PR (the owner's decision, `running-an-epic.md`). Each subtask is taken in from its worker, reviewed and gated locally, and merged locally into the integration branch. The rules of `tm-pr-workflow` apply to every step that has an equivalent (branch names, commits, the gate and its retry budget, the review and its fix budget); this file states what changes.

## Integrating a subtask

Everything runs in the main clone, one subtask at a time (`running-an-epic.md`, step 3.3):

1. **The branch is the plan's `branch`**, made with `git switch -c <branch> feature/epic/<slug>` (`spawning-subtasks.md`, "Workers"). It is local and is never pushed. The worker's commits come in with `scripts/subagent/worktree.sh take`.
2. **Bring it up to the integration tip.** When the integration branch advanced since the subtask's branch was made (a sibling merged first): `git merge feature/epic/<slug> --no-edit` into the subtask branch, in its own tool call. The merge result is then what will be merged, so the gate runs on the tree that lands. A conflict means two subtasks' `allowed_paths` overlapped: a plan defect, stop and report. This is a new commit, not a retry-budget attempt.
3. **Scope check.** `git diff --name-only feature/epic/<slug>...HEAD` lists only files matching `allowed_paths` (`worktree.sh take` already refuses a worker's commit outside them; this is the orchestrator's own check). The subtask never touches `BOARD.md`: its follow-ups and drift go to `keep-notes.md`.
4. **The draft description is the local review's `TASK`.** At `~/agent-workspace/epics/<slug>/keep-pr-body-<id>.md`, with the headings of `tm-pr-workflow`, "PR description": `Epic: <slug> · Subtask <id> · depends_on: <ids>`, a line `allowed_paths: <the plan's list>`, "What changed" with the scope check's output and the **review scope** line below, the subtask's `tier2` line with the tests' real names under Tier 2, Tier 1 (the gate's result, filled in after it), and `Board: no changes`.
   - **Review scope.** `scripts/local-review-prepare.sh` compares with the merge-base with `origin/main`, so on a subtask branch the local reviewer sees the whole epic diff so far, earlier subtasks included. The description says that the scope is the commits `feature/epic/<slug>..HEAD` of this subtask and judges them against its acceptance. A `--base` option of the script would remove the workaround; it is a script change left to the owner (board record `epic-subtask-review-base`). The whole-branch review at the end has the right base (`running-an-epic.md`, step 4.4).
5. **Local review** (`tm-agent-loop`, section 4): `scripts/local-review-prepare.sh <draft>`, the `pr-reviewer`, `scripts/local-review-record-verdict.sh`. A `[blocking]` finding is fixed as a new commit and reviewed again (budget: 2 review fix attempts); a verdict of `ESCALATE_TO_HUMAN` with no blocking finding is not a stop in an epic: its notes go to `keep-notes.md` and to the epic PR's "For the owner" part, where the human sees them; each `[important]` gets a disposition (`fixed in <sha>`, `rejected: <reason>`, or a follow-up noted for the board commit).
6. **Gate**: `scripts/pre-push-check.sh` on the subtask branch HEAD (`tm-pr-workflow`, "Tier 1"; the same retry budget). Once an earlier subtask touching the shared layer is merged, every later subtask runs the iOS steps, including an Android-only one, because the epic's shared changes are in its diff: expected, since it builds iOS against the integrated shared layer. The gate's result goes in the subtask's draft and in `keep-run.log`.
7. **Merge locally**: `git switch feature/epic/<slug>`, then
   `git merge --no-ff <branch> -m "<type>(<scope>): <summary> (subtask <id>)" -m "Epic-Subtask: <id>" -m "<the attribution trailer>"`.
   The merge commit names the subtask in the trailer `Epic-Subtask: <id>`: that trailer is how a resumed run knows what is merged (`running-an-epic.md`, step 3.1). `--no-ff` keeps the worker's commits and the red-test evidence in their messages. The title is a valid `type(scope): summary`.
8. **Clean up**: `scripts/subagent/worktree.sh remove <name>` (already done before the review), delete the subtask branch (`git branch -d`), and log `merged` with the merge commit.

There is no push, no PR, no CI run and no Merge check for a subtask. The push hook is not involved until the one push of the whole branch.
